Lire le système avant le code

Le modèle mental de Lazy Bird.

Ce manuel décrit les frontières, les flux, les contrats et les points d'extension de l'application. Il doit permettre à un agent de modifier le système sans reconstruire son contexte fichier par fichier. /docs reste la référence interactive des signatures HTTP ; cette page explique comment le comportement est assemblé.

Règle de lecture
Endpoint → schéma → CRUD/service → session → modèle ou adaptateur. main.py assemble le système ; il ne porte pas les cas métier.

Architecture en couches qui décide de quoi ?

Les dépendances vont des interfaces vers les cas d'usage, puis vers les intégrations. Les modules dynamiques sont découverts, mais leur surface est contrôlée par un contrat.

Interface

FastAPI reçoit, valide et traduit les erreurs en statuts HTTP.

Cas d'usage

Les CRUD ouvrent la session et coordonnent la persistence.

Persistence

SQL conserve identités et états ; le vectoriel conserve contenu et vecteurs.

Intégrations

Storage, Hugging Face, formats et engines restent remplaçables.

Chemin de lecture onboarding

  1. main.py : démarrage et refus 503.
  2. api/__init__.py : découverte des routers.
  3. schemas/, puis le CRUD de la ressource.
  4. models/ et la migration propriétaire.
  5. database/, storage ou plugin appelé.
  6. Le test miroir qui prouve le comportement.

Règles de conception garde-fous

Responsabilité unique

Endpoint = HTTP, schema = validation, CRUD = use case, storage = fichiers, modèle = persistence.

Dépendances

Les couches internes ne dépendent pas de FastAPI ; les intégrations sont doublables.

Contrats stricts

Settings Pydantic avec clés inconnues refusées ; plugin incomplet = erreur claire.

Secrets

APIKeyIn accepte la clé, APIKeyOut ne la renvoie jamais.

Démarrage et mode dégradé ordre strict du lifespan

Le serveur est créé même si l'initialisation échoue. Le middleware protège toutes les routes sauf /, qui expose l'erreur sans exécuter de logique métier incomplète.

01 · SQL

initialize_selected_sql_database() choisit l'adaptateur, applique alembic upgrade head et vérifie la révision.

02 · Auth

authenticate_hf() cherche HuggingFace ; son absence est un warning.

03 · Catalogue

sync_cached_models() importe les snapshots, puis les engines sont upsertés.

04 · Vectoriel

L'adaptateur sélectionné est initialisé et catalogué par vector_database.populate().

Échec et reprise La première erreur devient app.state.startup_error. GET / la renvoie ; les autres routes répondent 503. Corriger puis redémarrer.

Découverte des routers règle d'import

Au chargement de api, pkgutil.iter_modules parcourt api/endpoints. Chaque module doit exporter router, sinon l'application lève ImportError.

Ajouter un endpoint Créer le module, le router, les schemas et l'appel CRUD. Aucun ajout manuel dans api/__init__.py.

Migrations Alembic source de vérité

  1. Modifier le modèle et l'import de models/__init__.py.
  2. Créer une révision depuis src/lazy_bird.
  3. Relire upgrade() et downgrade() en préservant les données.
  4. Tester base vide et base peuplée.
  5. Vérifier que alembic_config_for(url) impose l'URL à env.py.
Interdit en production Ne pas restaurer SQLModel.metadata.create_all() dans le démarrage. test_db() est réservé aux tests explicites.

Fichiers et stockage frontière physique

storages/__init__.py résout les chemins, crée les dossiers, copie les octets et calcule les métadonnées. Il ne touche ni SQL ni HTTP.

Tout chemin client est non fiable : absolus, .., séparateurs Windows et sortie du dossier d'upload sont refusés. Les fichiers vivent dans storages/uploads/.

Le coordinateur est crud/await_file.py. Il crée ou réinitialise Embedded, lance le chunker, génère les vecteurs, remplace l'index et met à jour les statuts. Sans modèle sélectionné, la file reste en attente.

Chunking et formats chuncker/

  1. _extension_module() normalise l'extension et importe chuncker.extensions.<ext>.
  2. _selected_context() utilise selected_context, sinon max_context_length, et refuse une valeur invalide.
  3. Le module expose async Chunck(file, max_token) ; l'orchestrateur ignore le détail du format.
  4. Markdown sépare front matter et paragraphes, encode avec cl100k_base, découpe avec overlap et conserve lignes/colonnes.
  5. Chaque chunk transporte content, positions et meta_data.
Erreurs Module absent → format-error ; exception parser → chunck-error. La fonction publique est nommée Chunck par contrat historique.

Embedding résolution + batching

  1. Réimporter l'engine sélectionné depuis file_path.
  2. Valider ses kwargs avec EngineSettings.
  3. Vérifier modèle et format supporté.
  4. Injecter local_path dans model_path si prévu.
  5. Appeler embed par lots et exiger un vecteur par entrée.

Persistance vectorielle chunks hors SQL

SQL conserve identité et traçabilité. LanceDB crée une table par modèle normalisé ; chaque ligne contient contenu, métadonnées JSON, embedded_id et vecteur. Une ré-indexation supprime les lignes du même embedding avant d'ajouter le lot.

Modèles Hugging Face téléchargement, extraction, cache

Création

crud/llm_model.py appelle snapshot_download, puis enregistre chemin local et métadonnées.

Extraction

tools/model_extraction.py lit config.json pour nom, dimension, contexte et formats ; onnx/ ajoute ONNX.

Cache

hf_cache_worker.py reconnaît models--org--repo/snapshots/<revision> sous HF_HUB_CACHE.

Testabilité

hf_auth.py, cache et extraction sont doublables ; aucun test standard ne dépend du réseau.

Contrats d'extension ajouter sans modifier le noyau

Les plugins sont des modules Python découverts automatiquement. Un contrat incomplet doit produire une erreur explicite à l'enregistrement.

SQL adapter

name, initialize(**settings) → Engine, disconnect(engine, drop=False).

Vector adapter

name, initialize, disconnect, create, delete, retrieve.

Embedding engine

name, formats, EngineSettings, validate_kwargs, embed(chunks, ctx_size, batch_size, settings).

Format extension

async Chunck(file, max_token) → liste de dictionnaires compatibles.

Exemple minimal d'engine
name = "my-engine"
formats = ["safetensors"]

class EngineSettings(BaseModel):
    device: str | None = None
    model_path: str | None = None
    model_config = ConfigDict(extra="forbid")

def embed(chunks, ctx_size, batch_size, settings):
    texts = [item["content"] if isinstance(item, dict) else str(item) for item in chunks]
    return load(settings.model_path).encode(texts, batch_size=batch_size)

Recettes pour modifier le code chemins vérifiables

Ressource métier

Modèle + migration, schema entrée/sortie, CRUD, endpoint et tests modèles/schemas/CRUD/endpoint. Pas de SQL dans l'endpoint.

Embedding-engine

Créer le module, déclarer le contrat, tester kwargs et nombre de vecteurs, démarrer pour l'upsert, sélectionner engine et modèle.

Format

Créer chuncker/extensions/ext.py, implémenter Chunck, tester budget, positions, métadonnées et parsing.

Base

Créer adaptateur et Settings strict, tester découverte/initialisation/sélection/déconnexion ; SQL doit être au head Alembic.
